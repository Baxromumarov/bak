Bootstrap binaries present in repo root:
- bakc-stage0 (Go-built compiler)
- bakc-stage1 (native)
- bakc-stage2 (native)

Observed bootstrap behavior:
1. stage1 -> stage2 self-compile: PASS
   command:
   `./bakc-stage1 native src/compiler/cmd/bakc/main.bak -o /tmp/bakc-stage2-time`

2. stage2 -> stage3 self-compile: PASS
   command:
   `./bakc-stage2 native src/compiler/cmd/bakc/main.bak -o /tmp/bakc-stage3-time`

3. Deterministic stage hash (stage2 vs stage3): FAIL
   - sha256(/tmp/bakc-stage2-time) = 4c6911285eb36ab62d88201fdb50a092caad96a2aaa76e5ef50124c57da6e0bc
   - sha256(/tmp/bakc-stage3-time) = fa2d4d895abbfcbf49f7a85fe59428c744889062e175046a796391bb89562797

4. Memory envelope (informational, measured with `/usr/bin/time -v`): FAIL for 1GB target
   - stage1 -> stage2 max RSS: 1933856 KB (~1.84 GB)
   - stage2 -> stage3 max RSS: 2155868 KB (~2.06 GB)

Native smoke checks:
- PASS: `./bakc-stage1 native examples/hello.bak -o hello && ./hello`
- PASS: `./bakc-stage2 native examples/hello.bak -o hello && ./hello`
- PASS: `tests/native_fs_readwrite.bak` (stage1 and stage2)
- FAIL: `tests/native_os_cwd_test.bak` (prints "Error getting cwd")
- FAIL: `tests/native_os_exec_test.bak` (prints "FAIL: exec failed")
- FAIL: `tests/native_vec_struct_push.bak` (runtime exit code 26)
- FAIL: `tests/native_vec_struct_literal.bak` (runtime exit code 10)
- PARTIAL: `examples/variables.bak` and `examples/enums.bak` run but lose value output

Interpretation:
- Native pipeline is operational but not production-correct yet.
- Major blockers shifted from "cannot self-compile" to correctness + determinism + memory.

================================================================================
                         CRITICAL BLOCKERS TO FINISH
================================================================================

P0 blockers (must fix before release):
1. Determinism failure between stage2 and stage3 outputs.
2. Memory budget miss: self-host peaks around 1.8-2.1 GB instead of <=1 GB no-swap.
3. Runtime correctness failures in Vec<struct> paths:
   - tests/native_vec_struct_push.bak
   - tests/native_vec_struct_literal.bak
4. Native os behavior gaps:
   - tests/native_os_cwd_test.bak
   - tests/native_os_exec_test.bak
5. Formatting/value materialization issues in output paths:
   - value printing/conversion regressions visible in variables/enums/vector demos.

P1 blockers (close before production sign-off):
1. Remove temporary bootstrap guards/workarounds in driver/module_graph/native backend
   once correctness is restored.
2. Eliminate remaining debug instrumentation from self-host path.
3. Publish reproducible evidence artifacts for all production gates.

================================================================================
                                FINISH PHASES
================================================================================

PHASE F1 - Correctness Stabilization (highest priority)
--------------------------------------------------------
Objective:
- Make stage2 behavior match stage0 for core language/runtime scenarios.

Tasks:
- Fix Vec<struct> runtime/codegen corruption paths (push/literal/index).
- Fix os.cwd and os.exec syscall/runtime wiring and error mapping.
- Fix value formatting/conversion path used by println/string conversion.
- Promote failing smoke cases above to permanent regressions.

Exit criteria:
- All failing smoke checks above pass under stage2.
- No crashes/abnormal exits in vec struct tests.

PHASE F2 - Determinism
----------------------
Objective:
- Ensure stage2 and stage3 outputs are byte-identical for compiler binary.

Tasks:
- Audit nondeterministic inputs: map iteration order, symbol/data section ordering,
  relocation/call patch order, generated constant table ordering.
- Add stable ordering where required.
- Add deterministic hash check script and CI assertion.

Exit criteria:
- `sha256(stage2) == sha256(stage3)` in 3 consecutive clean runs.

PHASE F3 - Memory Budget
------------------------
Objective:
- Bring self-host compile under 1GB memory with swap disabled.

Tasks:
- Profile allocation hotspots in native emit path (especially method call/lowering).
- Reduce transient allocations in AST/type/lowering loops.
- Replace copy-heavy loops with borrow/reference traversal where safe.
- Add memory-budget CI job (`MemoryMax=1G`, `MemorySwapMax=0`).

Exit criteria:
- stage1 -> stage2 and stage2 -> stage3 both pass under 1GB/no-swap.

PHASE F4 - Gate Evidence and Release Hygiene
--------------------------------------------
Objective:
- Close Gate 0..6 evidence requirements and document final workflow.

Tasks:
- Refresh docs/PRODUCTION_READINESS_TRACKER.md with current measurements.
- Attach command logs for stage chain, hashes, RSS/time, regression matrix.
- Update BOOTSTRAP.md to canonical workflow based on fixed stage status.
- Finalize release checklist/changelog/policies.

Exit criteria:
- Gate tracker rows all PASS with linked evidence artifacts.

PHASE F5 - Repository Cleanup (after gates pass)
-------------------------------------------------
Objective:
- Transition repo to native compiler of record with historical Go archive policy.

Tasks:
- Archive or freeze legacy Go compiler paths per release governance policy.
- Keep only required compatibility tooling paths active.

Exit criteria:
- No active release dependency on Go compiler path.
