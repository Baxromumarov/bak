You are a senior systems engineer and language tooling expert.

I have a Go-based programming language project called "bak". It currently includes a CLI, compiler pipeline (lexer, parser, typechecker, compiler), VM runtime, native code generation, test runner, and package manager — but everything is tightly coupled, with large files (especially main.go), duplicated logic, and poor separation of concerns.

Your task is to **fully refactor and redesign the architecture of this project** for scalability, clarity, and maintainability.

---

# 🎯 Goals

Refactor the project to achieve:

1. Clean architecture with strict separation of concerns
2. No duplicated compiler logic (parse/typecheck/compile should be centralized)
3. Modular CLI design (no large switch-case in main)
4. Improved readability and maintainability
5. Clear execution model (VM vs native vs interpreter)
6. Elimination of fragile patterns (like string-based code generation)
7. Production-grade structure similar to modern tools

---

# 🏗️ Required Architecture

You MUST reorganize the project into this structure:

* cmd/bak/main.go → CLI entrypoint ONLY
* internal/cli/ → command system (registry, context, commands)
* internal/pipeline/ → compiler pipeline (parse, typecheck, compile, run, build)
* internal/config/ → runtime permissions + feature flags + bak.toml
* internal/runner/ → execution (VM, native, REPL)
* internal/pkgmgr/ → package manager (get/install/cache/lock)
* internal/test/ → test discovery + runner (NO string code generation)
* pkg/ → keep existing compiler/runtime code (lexer, parser, etc.)

---

# ⚙️ Refactoring Requirements

## 1. CLI

* Replace switch-based CLI with a command registry pattern

* Each command must implement:

  type Command interface {
  Name() string
  Description() string
  Run(ctx *Context, args []string) error
  }

* Implement commands: run, build, test, check, doctor, repl

* Move all logic out of main.go

---

## 2. Context Object

Introduce:

type Context struct {
Permissions runtimecap.Permissions
Features    []string
Trace       bool
WorkingDir  string
}

All commands MUST use this instead of passing multiple flags.

---

## 3. Compiler Pipeline

Create reusable pipeline:

type Pipeline struct {
Filename string
Source   string
AST      *ast.Program
Module   *compiler.Module
}

Implement stages:

* Parse
* Typecheck
* Compile
* RunVM
* BuildNative

ALL commands must use this pipeline instead of duplicating logic.

---

## 4. Execution Model

Unify behavior:

* "build" → native ONLY
* "run" → VM execution
* REPL → interpreter (optional)

Ensure consistent behavior across modes.

---

## 5. Test System

* REMOVE string-based test runner generation
* Replace with AST-based test runner builder
* Implement:

  * test discovery
  * AST construction for runner
  * execution via pipeline

---

## 6. Package Manager

* Move all package logic into internal/pkgmgr/
* Cleanly separate:

  * fetching
  * caching
  * lockfile
  * validation

CLI must only call pkgmgr APIs.

---

## 7. Code Quality Improvements

* Eliminate duplicated code paths
* Extract reusable helpers
* Improve naming consistency
* Reduce function size
* Ensure clear error handling
* Avoid global mutable state
