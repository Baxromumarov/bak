## 3. Syntax

### 3.1 Type Syntax

```bak
T box        // owned heap allocation
T box?       // optional owned heap allocation
```

Examples:

```bak
Tree box
Tree box?
User box?
Vec<int,_> box?
```

---

### 3.2 Construction

#### Box allocation

```bak
box T{ ... }
box T.new(args)
```

Examples:

```bak
var n = box Tree.new(5)
```

#### Optional construction

Use **standard enum constructors**:

```bak
Some(box T.new(...))
None
```

Examples:

```bak
left = None
left = Some(box Tree.new(3))
```

There is **no lowercase `some` / `none`** in the language.

---

## 4. Desugaring Rules (MANDATORY)

The compiler MUST apply the following transformations:

### Rule 1 - Type desugaring

```bak
T box?
```

is lowered to:

```bak
Option<T box>
```

internally.

---

### Rule 2 - Pattern matching

```bak
switch x {
    case Some(v) { ... }
    case None { ... }
}
```

works identically whether `x` was written as:

* `Option<T box>`
* `T box?`

---

### Rule 3 - No dual optional systems

The language MUST NOT have:

* a separate `box?` optional runtime
* lowercase `some` / `none`

There is **exactly one optional system**:

```
Option<T> with Some / None
```

---

## 5. Ownership and Move Semantics

### 5.1 `T box` ownership rules

* `T box` is **move-only**
* assignment moves ownership
* using after move is a compile-time error

Example (illegal):

```bak
var a = box Tree.new(1)
var b = a       // move
a.print()       // NO error: use after move
```

---

### 5.2 `T box?` ownership rules

* `Some(box T)` owns the box
* matching on `Some(v)` moves the box into `v`
* borrowing requires `&` or `&mut`

Example:

```bak
switch node.left {
    case Some(mut l) {
        l.insert(5)
    }
    case None {}
}
```

---

## 6. Mutability Rules

### 6.1 Mutation through box

Mutation of boxed values requires:

* the method is declared `mut func`
* the binding is mutable (`mut`)

Example (legal):

```bak
pub mut func insert(v: int) -> (void)
```

Example (illegal):

```bak
pub func insert(v: int) -> (void) {
    self.val = v   // NO mutation without mut
}
```

---

### 6.2 Pattern binding mutability

To mutate through `Some`, pattern binding must be `mut`:

```bak
case Some(mut l) { ... }   // OK
case Some(l) { l.insert() } // NO if insert is mut
```

---

## 7. Drop / Destruction Semantics

* `box T` is dropped automatically when its owner goes out of scope
* `T box?`:

  * `None` -> nothing to drop
  * `Some(box T)` -> drop `T`

Drop order:

* deterministic
* depth-first
* no GC required

---

## 8. Borrowing Rules

Borrowing from boxed values follows standard bak borrowing rules.

Examples:

```bak
func inspect(t: &Tree box) -> (void)
func modify(t: &mut Tree box) -> (void)
```

You cannot:

* borrow after move
* mutably borrow while immutable borrows exist

---

## 9. Equality and Copying

* `box` values are **not copyable**
* equality is:

  * **not defined by default**
  * may be implemented manually

This avoids accidental deep comparisons.

---

## 10. Prohibited Constructs (MUST ERROR)

The compiler MUST reject:

1. Copying boxed values
2. Mixing lowercase `some` / `none`
3. Treating `box?` as a separate optional system
4. Implicit allocation (no hidden `box`)
5. Mutation without `mut`
6. Using moved boxes

---

## 11. Canonical Example (Normative)

```bak
struct Tree {
    val: int
    left: Tree box?
    right: Tree box?
}

impl Tree as t {

    pub func new(val: int) -> (Tree) {
        return Tree{
            val: val,
            left: None,
            right: None,
        }
    }

    pub mut func insert(v: int) -> (void) {
        if v < t.val {
            switch t.left {
                case Some(mut l) {
                    l.insert(v)
                }
                case None {
                    t.left = Some(box Tree.new(v))
                }
            }
        } else {
            switch t.right {
                case Some(mut r) {
                    r.insert(v)
                }
                case None {
                    t.right = Some(box Tree.new(v))
                }
            }
        }
    }
}
```

This example **must compile** and **must be memory-safe**.

## 12. LSP Requirements

The LSP MUST:

* show `T box?` as an optional boxed type
* display hover info as:

  ```
  left: Option<Box<Tree>>
  ```
* suggest `Some` / `None` in completions
* show ownership/mutability info on hover

---

## 13. Implementation Checklist

### Parser

* recognize `box` and `?`
* allow `T box?` only in valid positions

### Type Checker

* desugar `T box?`
* enforce move-only semantics
* enforce mutability rules

### Borrow Checker

* treat box contents as owned memory
* enforce aliasing rules

### VM / Runtime

* allocate heap objects for `box`
* store pointer/handle
* deterministic drop

---

## 14. Final Law (Put This in the Language README)

> **`T box?` is optional ownership, not a pointer.
> It uses `Option`, not magic.
> Ownership is explicit, mutation is explicit, and nothing is implicit.**
