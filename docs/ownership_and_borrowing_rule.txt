
# Borrowing and Ownership in bak v1

Borrowing in bak v1 is a simple, lexical model: read-only vs mutable access, with no escaping, lifetimes, or counters.

## Supported Borrows
- `&T` — read-only borrow
- `&mut T` — mutable borrow

## Core Rules
1. **Passing by value moves:**
    - `consume(nums)` moves `nums`; it cannot be used after.
2. **Borrowing does not move:**
    - `inspect(&nums)` leaves `nums` valid.
3. **At most one mutable user at a time:**
    - Only one `&mut` allowed; no simultaneous borrows or moves.

## Not Supported in v1
- Returning borrowed values
- Storing borrows in structs
- Borrowing fields independently
- Nested/reborrowed borrows
- Lifetime inference
- Borrowing across function boundaries
All are compile-time errors.

## Compiler Logic
- Each variable is: Owned, Moved, or BorrowedMut
- No need for borrow counters or lifetime tracking

**Checker logic:**
- Use: must be Owned
- `consume(x)`: require Owned, mark as Moved
- `&x`: require Owned
- `&mut x`: require Owned, mark as BorrowedMut, clear at end of scope
- While BorrowedMut: forbid `&x`, `&mut x`, `consume(x)`

## Guarantees
- No use-after-move
- No mutable aliasing
- No mutation through shared access
- No dangling references

## Examples
**Must fail:**
```
var v Vec<int,_> = Vec.from([1,2,3])
consume(v)
consume(v)
```
**Must pass:**
```
var v Vec<int,_> = Vec.from([1,2,3])
inspect(&v)
inspect(&v)
```
**Must fail:**
```
mut var v Vec<int,_> = Vec.from([1,2,3])
modify(&mut v)
inspect(&v)
```
**Must pass:**
```
mut var v Vec<int,_> = Vec.from([1,2,3])
{
     modify(&mut v)
}
inspect(&v)
```

## Rationale
- Simple, easy to reason about and implement
- No need for Rust-level complexity in v1
- Can be extended in future versions without breaking v1 code
