# Borrowing and Ownership in bak v1

Bak's ownership model is intentionally small: moves are explicit through by-value use, borrows are lexical, and diagnostics should tell you whether a value was moved or is still borrowed.

## Supported borrows
- `&T`: shared read-only borrow
- `&mut T`: exclusive mutable borrow

## Core rules
1. Passing a non-copy value by value moves it.
   Example:
   ```bak
   func consume(data Data) -> (void) {}

   func main() -> (void) {
       var data: Data = Data{value: "bak"}
       consume(data)
       consume(data) // error: use of moved value 'data'
   }
   ```
2. Borrowing does not move the owner.
   Example:
   ```bak
   func inspect(nums: &Vec<int, _>) -> (int) {
       return nums.len()
   }

   func main() -> (void) {
       var nums: Vec<int, _> = Vec.from([1, 2, 3])
       inspect(&nums)
       inspect(&nums) // OK
   }
   ```
3. A mutable borrow is exclusive.
   Example:
   ```bak
   func grow(nums: &mut Vec<int, _>) -> (void) {
       nums.push(4)
   }

   func main() -> (void) {
       mut var nums: Vec<int, _> = Vec.from([1, 2, 3])
       var shared = &nums
       grow(&mut nums) // error: cannot borrow 'nums' as mutable because it is already immutably borrowed
       println(shared.len())
   }
   ```
4. Block boundaries end temporary borrows.
   Example:
   ```bak
   func grow(nums: &mut Vec<int, _>) -> (void) {
       nums.push(4)
   }

   func inspect(nums: &Vec<int, _>) -> (int) {
       return nums.len()
   }

   func main() -> (void) {
       mut var nums: Vec<int, _> = Vec.from([1, 2, 3])
       {
           grow(&mut nums)
       }
       inspect(&nums) // OK
   }
   ```

## What v1 rejects
- Returning borrowed values
- Storing borrows inside structs or enums
- Reborrowing through another borrow
- Field-level independent borrow tracking
- Lifetime inference or non-lexical borrows

These are compile-time errors by design in v1.

## What the checker tracks
- Owned values that are still usable
- Values moved by assignment, return, or call
- Active immutable borrows
- Active mutable borrows

That is enough to catch:
- use-after-move
- move-while-borrowed
- double mutable borrow
- mutable-vs-immutable borrow conflicts

## Diagnostic expectations
- Move errors should explain where the move happened.
- Borrow errors should explain the conflicting state.
- Mutability errors should suggest `mut var` or `mut func` when that is the actual fix.
